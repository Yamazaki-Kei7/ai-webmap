# 要件定義書 - チャットで主題図を作る AI Web マップ

## 1. 目的

Felt AI のように、ブラウザ上で LLM とチャットするだけで主題図を作成できることを技術検証する。

検証したい問いは次の 3 つ。

1. LLM が自然言語の依頼から、データを選び、SQL を書き、シンボルとラベルを設定して主題図を完成させられるか。
2. S3 に置いた GeoParquet を、ブラウザ内の DuckDB-WASM から直接クエリする構成が全国規模のデータで成立するか。
3. AWS Blocks の `Agent` ブロックで「ブラウザ側で実行するツール」を実用的な応答時間で回せるか。

本プロジェクトは技術検証用のデモアプリであり、本番運用は想定しない。将来はデータベースやオブジェクトストレージへのクエリに発展させる想定で、今回は S3 上のファイルをクエリする方式に限定する。

## 2. 機能要件

### 2.1 必須機能（フェーズ 1）

**チャット**

- [ ] サインインしたユーザーが、画面右のチャットパネルから日本語で依頼を送れる。
- [ ] LLM の応答がストリーミングで表示される。
- [ ] ツールの実行状況（クエリ実行中、レイヤー追加など）がチャット内に表示される。
- [ ] LLM は現在の地図状態（レイヤー、列、スタイル）を踏まえて応答する。パネルでの手動操作の結果も LLM に伝わる。

**レイヤーの追加**

- [ ] チャットの依頼で、国土数値情報のデータセットをレイヤーとして地図に追加できる。
- [ ] 属性による絞り込みができる（例: 札幌市の地価公示だけ）。
- [ ] 集計ができる（例: 市区町村ごとの学校数）。
- [ ] 空間結合ができる（例: 行政区域ポリゴンに含まれる駅を数えて塗り分ける）。
- [ ] チャットの依頼でレイヤーを削除できる。

**シンボルの設定**

- [ ] 単一色、カテゴリ分類、段階区分、比例シンボル（点のみ）の 4 種を、チャットで設定・変更できる。
- [ ] 段階区分は分類法（等量、等間隔、手動）と階級数を指定できる。
- [ ] 配色は名前付きの固定セットから選べる。
- [ ] 不透明度、線幅、枠線、点サイズを指定できる。

**ラベルの設定**

- [ ] 任意の列をラベルとして表示・解除できる。
- [ ] 文字サイズ、色、縁取り、表示開始ズームを指定できる。

**視点の操作**

- [ ] チャットの依頼で、レイヤー全体、指定範囲、指定した中心とズームへ移動できる。
- [ ] 地名による移動は、行政区域や駅のデータを引いて範囲を求める（外部ジオコーダは使わない）。

**レイヤー一覧と凡例**

- [ ] 画面左に、追加済みレイヤーの一覧をカードとして地図に重ねて表示する。
- [ ] 一覧から表示・非表示の切り替えと削除ができる。
- [ ] レイヤーごとに凡例（階級と色、カテゴリと色、円サイズ）を表示する。
- [ ] レイヤーごとに、LLM が生成した SQL を展開して確認できる。

**データ**

- [ ] 国土数値情報の 5 種（行政区域 N03、地価公示 L01、駅別乗降客数 S12、鉄道 N02、学校 P29）を全国分用意する。
- [ ] 変換スクリプトで GeoParquet とカタログ（`catalog.json`）を生成し、S3（`FileBucket`）に置く。
- [ ] 列名は意味のわかる名前に変換し、カタログに列の説明と統計値を持たせる。
- [ ] 出典を画面に表示する。

**認証**

- [ ] サインインしていないユーザーは地図とチャットを利用できない（Bedrock の課金を伴うため）。

### 2.2 必須機能（フェーズ 2）

- [ ] 作成した地図（レイヤー構成、スタイル、ラベル、視点）と会話を、ユーザーごとに保存できる。
- [ ] 保存した地図の一覧から、開く・新規作成・削除ができる。
- [ ] 復元時に一部のレイヤーが失敗しても、他のレイヤーは表示される。

### 2.3 オプション機能（今回は作らない）

- [ ] ユーザー自身のデータのアップロード
- [ ] データベース（PostGIS など）へのクエリ
- [ ] 地図の共有、公開 URL
- [ ] 自動保存
- [ ] レイヤーの並べ替え
- [ ] ベクトルタイル（PMTiles）による大規模データの描画
- [ ] ベースマップの画面上での切り替え

## 3. 非機能要件

### 3.1 パフォーマンス

以下は仮の目標値とし、スパイクと検証シナリオの結果で見直す。

- DuckDB-WASM と spatial 拡張の初期化は、初回アクセスで 10 秒以内に完了する。
- ツール呼び出し 1 回で済む依頼は、送信から地図への反映まで 15 秒以内を目標とする。
- 1 レイヤーの地物数に上限を設け、超過時は LLM に絞り込みや集計を促す。上限は設定値とする。
- クエリにタイムアウトを設ける。

### 3.2 セキュリティ

- チャットとデータ取得の API は、すべてサインインを必須とする。
- サインアップは不可能にする。公開 API からも、手作りの呼び出しからも、ユーザーは作れない。ユーザーは運用者だけが作る（Phase 1 開始前に変更。ユーザーの指示: サインアップ不可）。
- 利用許可ユーザーの一覧は残す。一覧にないユーザーは、アプリのすべての API で拒否する。サインアップ不可に加わる 2 層目の防御であり、ユーザーを削除せずに利用を止める手段でもある（Task 0.7 で追記。スパイク B-2 でデプロイ済みの動作を確認。Phase 1 開始前に位置づけを変更。ユーザーの指示: サインアップ不可）。
- 会話と保存した地図は、ユーザー単位で分離する。
- データファイルへは、期限付きの署名付き URL でのみアクセスさせる。
- LLM が生成する SQL は、`SELECT` と `WITH` の単文に限定する。外部 URL やファイル読み込み関数を含む SQL は拒否する。
- 1 ターンあたりのモデル呼び出し回数とツール呼び出し回数に上限を設け、暴走時の課金を抑える。

### 3.3 保守性

- スタイル、ラベル、ツール引数のスキーマは 1 か所で定義し、バックエンドとフロントエンドで共有する。
- スタイル指定から MapLibre の式への変換は純粋関数とし、単体テストで網羅する。
- 値のハードコードを避け、上限値、タイムアウト、ベースマップ URL などは設定値にまとめる。
- TypeScript で `any` と `unknown` を使わない。`class` を使わない。

### 3.4 互換性

- AWS Blocks のテンプレート構成（SvelteKit の静的 SPA、`framework: 'spa'`）を維持する。
- ローカル開発（`npm run dev`）と、サンドボックスおよび本番デプロイの両方で動作する。
- 最新版の Chrome を対象とする。他のブラウザは検証対象外とする。

## 4. 制約事項

### 4.1 技術的制約

- バックエンドは AWS Blocks の Building Blocks を使う（`AuthBasic`、`Agent`、`Realtime`、`FileBucket`、`DistributedTable`）。
- LLM は Amazon Bedrock の Claude Haiku 5.5 を使う。モデル ID は `jp.anthropic.claude-haiku-5-5`（`jp.` 推論プロファイル）で、`model.local` と `model.deployed` の両方に明示する。ローカル開発でも Bedrock を呼ぶ（Task 0.7 で変更。Sonnet 4.6 と Blocks の既定の `global.` プロファイルは、組織の SCP で拒否されるため使えない。「Haiku を全部で使う」はユーザーの決定、2026-11-17）。
- クエリはブラウザ内の DuckDB-WASM で実行する。サーバー側ではクエリを実行しない。データは GeoParquet をファイルごとに全体取得して登録する（Range 読み取りは使わない。Task 0.7 で追記、`docs/spikes.md` のまとめ）。
- `Agent` ブロックのツールはサーバー側で動くため、ブラウザでの実行にはカスタム interrupt を使う。
- 地図は MapLibre GL JS（`svelte-maplibre-gl`）を使う。
- サーバー専用の SvelteKit ファイル（`+page.server.ts` など）は使わない。

### 4.2 ビジネス制約

- 技術検証用のデモであり、本番品質の運用機能（監視、多言語対応、アクセシビリティ対応）は対象外とする。
- 国土数値情報はデータごとに利用条件が異なる。確認結果は `docs/data-sources.md` にある（採用版の 5 種のうち N03 は記載が食い違い、技術検証の範囲で使うとユーザーが判断した。検証用の環境（ローカルと、アプリ自身の非公開バケット）に限り、一般公開・配布・商用の前には測量法上の扱いを問い合わせる。Task 0.7 で追記）。
- AWS アカウントで Anthropic モデルが利用可能であることを前提とする。検証に使ったアカウントでは、`global.` プロファイル（Sonnet 4.6、Haiku 4.5）が SCP で拒否された。`jp.` の Haiku 5.5 は、ローカルとデプロイ後の実行ロールで呼べた（Task 0.7 で追記）。

## 5. 成功基準

### 5.1 完了の定義

- [ ] 冒頭のスパイク 3 件の結果が記録され、採用方式が確定している。
- [ ] 5 種のデータセットが S3 に置かれ、ブラウザからクエリできる。
- [ ] チャットだけで、レイヤー追加、4 種のシンボル設定、ラベル設定、視点移動ができる。
- [ ] レイヤー一覧と凡例が、地図の状態と常に一致している。
- [ ] 単体テスト、E2E テスト、型チェックがすべて通る。
- [ ] 検証シナリオ表（10 件程度）に、成否、ツール呼び出し回数、所要時間が記録されている。
- [ ] （フェーズ 2）保存した地図を再読み込み後に復元できる。

### 5.2 受け入れテスト

実際の Bedrock を使い、次の依頼がチャットだけで完結することを確認する。

- 「学校を種別で色分けして表示して」
- 「札幌市の地価を 5 段階で色分けして」
- 「市区町村ごとの駅の数で塗り分けて」
- 「乗降客数の多い上位 100 駅を円の大きさで表して、駅名をラベルにして」
- 「鉄道路線を追加して、JR だけ赤にして」
- 「さっきのレイヤーの色を青系に変えて」

## 6. 想定されるリスク

| リスク | 対策 |
|---|---|
| interrupt の往復が遅い、または複数回・並列の呼び出しで破綻する | 解消（Task 0.7）。スパイク A で、往復の追加時間が中央値 938 ms（ローカル）、1,010 ms（デプロイ後）で、複数回・並列も動いた。切り替えは不要。残る注意は設計 10.3 |
| DuckDB-WASM が署名付き URL を Range リクエストで読めない | 発生（Task 0.7）。設定だけでは読めなかったので、ファイル全体を取得して登録する方式に統一した。ファイルが数十 MB に育ったら見直す |
| ローカル開発から Bedrock を呼べない | 解消（Task 0.7）。`jp.anthropic.claude-haiku-5-5` で、ローカルでもデプロイ後でも呼べた。`global.` のモデルは SCP で拒否される |
| LLM の SQL が DuckDB spatial の方言とずれる | エラーを LLM に返して修正させる。プロンプトに書き方の決まりと例を入れる |
| 全国の行政区域ポリゴンが重い | 変換時に市区町村単位への統合と簡素化を行う。簡素化だけでは頂点が減らず、小さな島の除去が必須（スパイク B-1。Task 0.7 で追記） |
| spatial 拡張の取得元（DuckDB の配布サーバー）への外部依存 | 初期化失敗時にエラーと再試行を表示する |
| 国土数値情報の一部データに利用条件の制限がある | 準備時に規約を確認し、問題があればデータセットを差し替える |
| Bedrock の課金が想定を超える | 呼び出し回数の上限を設定し、認証と利用許可ユーザーの一覧を必須にする |
| Haiku の SQL・スタイルの生成やツール呼び出しの精度が足りない（Task 0.7 で追加） | モデルはユーザーの決定で Haiku に固定。プロンプトとツールのスキーマを小さなモデル向けに絞り（自由記述を減らし、例を入れる）、Task 4.5 と Task 5.1 で評価する。足りない場合はユーザーに報告して判断を仰ぐ |
| DuckDB-WASM（約 34 MB）をアプリのオリジンから配信できない（Task 0.7 で追加） | ホスト型プレビューの前面は返せなかった。アプリのバケットから署名付き URL で読み込む。CloudFront 前面からの配信は本番のホスティングを最初に行うときに測る |
| 運用者によるデプロイ先のユーザー作成の手順が、実機で未確認（Phase 1 開始前に変更。ユーザーの指示: サインアップ不可。旧: 開放のサインアップを止められない） | サインアップは自前の認証 API で拒否し、ユーザーは運用者だけが作る。デプロイ先でのユーザー作成は未確認で、Task 5.3 で確認する。動かなければ止めて再検討する（代替は `AuthCognito` の自己サインアップ無効）。利用許可ユーザーの一覧は 2 層目として残す |
